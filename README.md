# Мини-радар: бот для сбора заявок

Рабочий Telegram-бот на Python 3.12+, aiogram 3, SQLite и long polling.
Собирает два ответа, сохраняет заявку и доставляет её администратору через того же бота.
Сам мини-радар и анализ каналов не реализуются.

## Быстрый запуск

В [@BotFather](https://t.me/BotFather) отправь `/newbot`, задай имя и username.
Полученный токен нужен только в настройках окружения или локальном `.env`.
Не добавляй его в Git и не присылай в чат.

```bash
cd /path/to/radar_bot
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`:

```dotenv
BOT_TOKEN=токен_из_BotFather
ADMIN_TELEGRAM_ID=твой_числовой_User_ID
DATABASE_PATH=./data/bot.db
LOG_LEVEL=INFO
```

Свой User ID можно получить у `@userinfobot`. Другой вариант: временно указать
`ADMIN_TELEGRAM_ID=1`, запустить своего бота, отправить ему `/id`, затем остановить
бота, заменить ID на полученный и запустить снова. Username для админского доступа не используется.

```bash
python -m bot.main
```

На Windows (PowerShell) вместо активации Linux-окружения используй:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# Заполни .env в редакторе, затем:
.\.venv\Scripts\python.exe -m bot.main
```

Если `.env` уже создан, не копируй шаблон поверх него. При переносе на сервер
сначала останови локального бота (`Ctrl+C`): два процесса с одним токеном
будут конфликтовать при получении обновлений.

**Администратор должен первым открыть личную переписку со своим ботом и нажать `/start`.**
Telegram не позволяет боту первым начать переписку. До этого заявки сохраняются,
а уведомления остаются в очереди и повторяются автоматически.
Проверь получение заявки с другого Telegram-аккаунта. `/start` администратора открывает панель.

Настоящий токен нужен для реального запуска. В рабочем приложении нет mock API.
Сейчас в облачной среде токен и ID администратора не заданы; реальные отправки не проверены.

## Использование

- Пользователь: `/start`, «Хочу попробовать», два текстовых ответа до 1000 символов.
- Перед вопросами бот объясняет передачу ответов и Telegram ID администратору.
- `/cancel` отменяет только незавершённую анкету. Уже сохранённая заявка остаётся.
- `/start` продолжает незавершённую анкету или показывает существующую заявку.
- «Изменить заявку» запускает явное повторное заполнение. Исходная дата и номер
  сохраняются, версия увеличивается, прежние ответы остаются в истории, статус снова `NEW`.
- `/id` доступна всем; `/help` показывает доступные команды.
- Администратор: `/leads` с навигацией по 10 заявок, `/stats`, `/reply TELEGRAM_ID текст`.
- «Связался» устанавливает `CONTACTED`. Кнопка из старой версии не отмечает новую версию просмотренной.
- `CLOSED` предусмотрен в схеме и статистике; отдельного интерфейса закрытия в ТЗ нет.
- `/reply` отправляет сообщение только одному известному пользователю, начавшему личную переписку.
  Массовой рассылки нет. Текст передаётся без HTML-разметки.
- При отсутствии username бот использует `tg://user?id=...`. Открытие профиля/личного
  чата зависит от Telegram и настроек приватности; запасной способ — `/reply`.
- Бот принимает анкеты и администрирование только в личных чатах.

## Хранение и надёжность

База по умолчанию — `data/bot.db`, путь задаётся через `DATABASE_PATH`.
Каталог создаётся автоматически. Рабочий пользователь должен иметь право записи.
Время в базе — UTC, в карточке заявки — московское время.

В SQLite хранятся пользователи, анкеты FSM, одна текущая заявка на пользователя,
версии заявок и очередь уведомлений. Данные не зависят от памяти процесса.
Запись заявки, её версии, уведомления и завершение анкеты выполняются в одной транзакции.
Ограничения SQLite и идентификатор сообщения защищают заявку от повторного сохранения.
Первый ответ и переход ко второму вопросу тоже записываются атомарно.

Уведомления отправляет фоновый worker: первая попытка в пределах примерно 2 секунд,
затем задержки 5, 10, 20 секунд и далее до часа. Telegram `retry_after` учитывается.
Число попыток не ограничено; задача хранится до успешной отправки. В базе сохраняются
число попыток и класс последней ошибки, без текста ответов и секретов в логах.
После успешной отправки устанавливается `admin_notified_at` соответствующей версии.
При сетевом сбое после фактической отправки возможно повторное уведомление:
Telegram Bot API не предоставляет ключ идемпотентности. В карточках есть постоянный номер заявки.

Запускай **один экземпляр** на токен и базу: без нескольких реплик, нескольких workers
и одновременного запуска локально и на сервере. Long polling получает updates последовательно;
это намеренно простой режим для небольшого потока заявок. Другие пользователи не смешивают ответы.
При старте webhook отключается без удаления ожидающих updates.

## Тесты

```bash
source .venv/bin/activate
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты передают реальные модели Telegram Update в aiogram Dispatcher и подменяют
только HTTP-сессию Bot API. Временные SQLite-файлы настоящие. Сеть и токен не нужны.
Проверяются презентация, два вопроса, валидация, отмена, рестарт, изменение,
история и дубли, очередь и ошибки отправки, отсутствие username, админский ID,
команды администратора, отправка ответа и несколько пользователей.

## Резервная копия

Не копируй только `bot.db` при работающем боте: SQLite использует WAL.
Безопасная онлайн-копия стандартным SQLite backup API:

```bash
python deploy/backup.py data/bot.db /path/to/backups/radar-2026-11-12.db
```

Имя назначения должно быть новым; существующие копии не перезаписываются.
Скрипт проверяет целостность и устанавливает права `0600`. Храни копии отдельно от сервера.
Планирование ежедневного запуска можно сделать через cron/systemd timer.

Для восстановления останови бота, сохрани текущий каталог `data` отдельно,
помести копию на путь `DATABASE_PATH` без старых `-wal`/`-shm` рядом с ней,
восстанови владельца файла и запусти бота. Копия содержит персональные данные — ограничь доступ.

## Постоянный запуск на VPS (без Docker)

Нужны Linux, Python 3.12+, интернет до `api.telegram.org:443`, Git/загрузка файлов
и постоянный локальный диск. HTTP-сервер, домен и входящие порты не нужны.
Пример размещения: `/opt/radar_bot`, системный пользователь `radarbot`.

Администратор сервера создаёт пользователя, размещает проект, создаёт `.venv`,
устанавливает `requirements.txt` и заполняет `/opt/radar_bot/.env`.
В `.env` лучше указать абсолютный `DATABASE_PATH=/opt/radar_bot/data/bot.db`.
Каталог `data` должен принадлежать `radarbot`, `.env` — читаться только владельцем.

```bash
sudo useradd --system --home /opt/radar_bot --shell /usr/sbin/nologin radarbot
# Сначала размести файлы проекта в /opt/radar_bot, затем:
sudo mkdir -p /opt/radar_bot/data
sudo chown -R radarbot:radarbot /opt/radar_bot
sudo -u radarbot python3.12 -m venv /opt/radar_bot/.venv
sudo -u radarbot /opt/radar_bot/.venv/bin/pip install -r /opt/radar_bot/requirements.txt
sudo chmod 600 /opt/radar_bot/.env
sudo cp /opt/radar_bot/deploy/radar-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now radar-bot
sudo systemctl status radar-bot
sudo journalctl -u radar-bot -n 50 --no-pager
```

Если пути/пользователь отличаются — измени unit перед установкой.
При обновлении останови сервис, сделай копию базы, обнови файлы и зависимости,
затем перезапусти. Не удаляй `data` и `.env`. Входящий firewall открывать не нужно.

## deploy-f.com

**Поддержка конкретного тарифа deploy-f.com ещё не подтверждена.**
На момент проверки обращение к официальному сайту из облачной среды вернуло
403 от сетевого прокси; документация и панель сервиса не были доступны.
Это ограничение проверки, а не свидетельство несовместимости хостинга.

Для этого бота платформа должна поддерживать:

1. Постоянный фоновый процесс / worker без обязательного HTTP-порта и без засыпания.
2. Python 3.12+ с `pip install -r requirements.txt` либо сборку Dockerfile.
3. Постоянный диск для SQLite, сохраняемый при рестарте и новом деплое.
4. Переменные `BOT_TOKEN`, `ADMIN_TELEGRAM_ID`, `DATABASE_PATH`, `LOG_LEVEL`.
5. Исходящий HTTPS к `api.telegram.org` и ровно одну реплику.

Если есть Python worker: build command `pip install -r requirements.txt`,
start command `python -m bot.main`, working directory — корень репозитория.
`DATABASE_PATH` укажи внутри постоянного тома. Не используй временную файловую систему.
Не создавай HTTP health check для long polling: процесс не слушает порт.
Serverless/functions и веб-тариф с обязательным портом этому варианту не подходят.

Если доступна только контейнерная сборка, в проекте есть **необязательный** Dockerfile.
Сборка и пример локального запуска:

```bash
docker build -t radar-bot .
docker volume create radar-data
docker run -d --name radar-bot --restart unless-stopped \
  --env-file .env -e DATABASE_PATH=/app/data/bot.db \
  --mount source=radar-data,target=/app/data radar-bot
docker logs --tail 50 radar-bot
```

На платформе вместо локальной команды настрой Dockerfile, постоянный том `/app/data`
и переменные через панель. Контейнер работает от UID/GID `10001`; подключаемый каталог
должен разрешать этому пользователю запись. Порты публиковать не нужно.
Docker не требуется для обычного запуска на Python/VPS.

После размещения администратор нажимает `/start`, другой аккаунт заполняет анкету,
администратор проверяет уведомление и `/leads`. Затем перезапусти процесс и проверь,
что заявка сохранилась и незавершённая анкета продолжается. Только эта проверка
на выбранном тарифе подтверждает готовность к эксплуатации.
